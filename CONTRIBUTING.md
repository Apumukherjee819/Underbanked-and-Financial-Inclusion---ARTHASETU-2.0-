# Contributing to ARTHASETU 2.0

Thank you for your interest in contributing to ARTHASETU 2.0! We welcome contributions from developers, designers, and community members who want to help improve financial inclusion solutions for underbanked populations.

## Code of Conduct

We are committed to providing a welcoming and inclusive environment for all contributors. Please be respectful, professional, and supportive in all interactions. Any form of harassment, discrimination, or abusive behavior will not be tolerated.

## Getting Started

### Prerequisites
- Git installed on your system
- Node.js/npm or Python (depending on the project requirements)
- Familiarity with the project structure

### Setup Development Environment

1. **Fork the repository** on GitHub

2. **Clone your fork** locally:
   ```bash
   git clone https://github.com/YOUR_USERNAME/Underbanked-and-Financial-Inclusion---ARTHASETU-2.0-.git
   cd Underbanked-and-Financial-Inclusion---ARTHASETU-2.0-
   ```

3. **Add upstream remote** (to sync with the main repository):
   ```bash
   git remote add upstream https://github.com/Apumukherjee819/Underbanked-and-Financial-Inclusion---ARTHASETU-2.0-.git
   ```

4. **Install dependencies**:
   ```bash
   npm install
   # or
   pip install -r requirements.txt
   ```

## How to Contribute

### Reporting Bugs

Before submitting a bug report:
- Check if the bug has already been reported in the Issues section
- Provide clear, descriptive title and detailed description
- Include steps to reproduce the issue
- Specify your environment (OS, browser, version)
- Attach screenshots or logs if relevant

### Suggesting Features

- Describe the new feature and its benefits
- Explain why this feature would be useful for financial inclusion
- Provide examples or use cases
- Consider alternative solutions or features

### Submitting Pull Requests

1. **Create a feature branch**:
   ```bash
   git checkout -b feature/your-feature-name
   ```

2. **Make your changes**:
   - Write clean, readable code
   - Follow the project's coding standards
   - Add comments for complex logic
   - Include tests for new functionality

3. **Commit with clear messages**:
   ```bash
   git commit -m "feat: add descriptive message about your changes"
   git commit -m "fix: resolve issue with specific functionality"
   git commit -m "docs: update documentation for clarity"
   ```

4. **Keep commits clean**:
   - Make logical, atomic commits
   - Avoid committing unrelated changes
   - Rebase before submitting if needed

5. **Push to your fork**:
   ```bash
   git push origin feature/your-feature-name
   ```

6. **Create a Pull Request**:
   - Use a descriptive title
   - Reference related issues (e.g., "Fixes #123")
   - Provide context about your changes
   - Include screenshots for UI changes
   - Ensure all tests pass

## Development Workflow

### Testing

- Write unit tests for new features
- Run existing tests before submitting PRs
- Aim for adequate code coverage
- Test edge cases and error scenarios

### Code Style

- Follow existing code conventions in the project
- Use meaningful variable and function names
- Keep functions small and focused
- Comment complex or non-obvious code

### Documentation

- Update README if your changes affect setup or usage
- Document API changes or new features
- Add inline comments for complex logic
- Update CHANGELOG.md with your changes

## Review Process

1. Maintainers will review your PR
2. Address feedback and suggestions
3. Make requested changes in new commits
4. Once approved, your PR will be merged

## Commit Message Guidelines

Use conventional commit format:
- `feat:` for new features
- `fix:` for bug fixes
- `docs:` for documentation changes
- `style:` for code style changes (formatting, etc.)
- `refactor:` for code refactoring
- `test:` for test additions or modifications
- `chore:` for dependency updates and other chores

Example: `feat: add user authentication module`

## Project Structure

The repository is organized as follows:
- `/src` - Source code
- `/tests` - Test files
- `/docs` - Documentation
- `/config` - Configuration files
